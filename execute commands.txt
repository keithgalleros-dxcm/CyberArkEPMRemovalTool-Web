EXECUTE COMMANDS - PORTAL + VISITING-PC CONNECTOR
Updated November 19, 2026

IMPORTANT TARGETING CHANGE
The LAN portal uses a connector on each visiting PC/VM. It no longer scans or
modifies the portal host as a fallback when a remote browser opens the site.
A browser alone cannot inspect installed agents, services, or UAC state.
Run the connector INSIDE the VM if the VM is the intended endpoint.
This guide does not execute commands automatically.

PREREQUISITES
- Python 3.11+ on the portal server AND each endpoint running a connector.
- Official Windows Python: https://www.python.org/downloads/windows/
- Windows setup: https://docs.python.org/3/using/windows.html
- No pip packages, Node.js, Docker, .NET SDK or database needed for Python.
- Browser JavaScript, cookies and local storage enabled.
- Portal TCP 8765 reachable from endpoints. No inbound endpoint port needed.
- Windows UAC/admin approval on the ENDPOINT for agent changes; root/sudo
  for macOS/Linux installation. Portal admin is only needed for its firewall
  setup or intentional standalone host operations.
- Private Cyberark Agents library on the portal (about 409 MiB supplied),
  plus temporary staging and vendor-required installed-agent disk space.
- Network connectivity to the configured EPM service and required Linux
  package repositories. Vendor OS/CPU/prerequisite support still applies.

ONE-TIME FIREWALL SETUP (Administrator PowerShell on the portal laptop):
    Set-Location 'C:\Users\Keith\source\repos\CyberArkEPMRemovalTool\webapp'
    $pythonPath = py -3 -c "import sys; print(sys.executable)"
    powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Enable-LanFirewall.ps1 -LocalAddress 192.168.1.101 -RemoteSubnet 192.168.1.0/24 -PythonPath $pythonPath

The helper supports this matching /24, local IP, program and TCP port only.
It leaves an existing named rule unchanged; review that rule if needed.
ExecutionPolicy Bypass is process-scoped; it does not grant admin rights.

Keep the terminal open.

C. CONNECT A WINDOWS PC OR VM (FIRST TIME)

Do these steps INSIDE the target Windows PC/VM, not on its VMware host.
1. Verify Python in that PC's PowerShell:
       py -3 --version
2. Open the LAN portal URL and sign in with the portal's LAN access code.
3. Click Download connector for this PC.
4. Extract endpoint-connector.zip into your private LOCAL user folder.
5. Run Start connector.cmd by double-click, or from PowerShell in that folder:
       & '.\Start connector.cmd'
   Equivalent direct command:
       py -3 endpoint_connector.py --config connector.private.json
6. Keep that console open. The connector opens the paired portal in the
   default browser. If that browser is not signed in, enter the LAN code.
7. The portal now shows that endpoint's hostname, OS, agent and privileges.
   Compare the name with this read-only command INSIDE the VM:
       $env:COMPUTERNAME
8. Click Request administrator access when needed; approve UAC on THIS PC.
   The connector relaunches elevated and the portal reconnects to it.
9. Select the matching platform/workspace. Type the endpoint hostname and
   explicit INSTALL/UNINSTALL confirmation as required before an operation.

No inbound firewall rule is required on the endpoint. The connector makes
outbound requests to the portal. Do not disable browser network protections.
A private kit is fetched/staged only for an explicit installation. Starting
or pairing the connector does not install or remove CyberArk automatically.

D. MACOS / LINUX ENDPOINT CONNECTOR

Download and extract a fresh connector kit using the target PC's browser.
In that extracted folder:
    python3 --version
    sh start-connector.sh

Equivalent:
    python3 endpoint_connector.py --config connector.private.json

For approved root operations, stop the read-only connector after all jobs
finish, then use the exact sudo command shown by that endpoint's portal
privilege panel. General form from the extracted folder:
    pythonPath="$(python3 -c 'import sys; print(sys.executable)')"
    sudo "$pythonPath" endpoint_connector.py --config connector.private.json --resume --no-open-browser

Passwords are entered only in the native terminal/UAC prompt, not the portal.
macOS may need extension/Full Disk Access approvals. Linux removal remains
manual; installation is enabled only for the supplied compatible distro kit.

E. PAIRING / STOPPING / UPDATING

- Use a separate freshly downloaded kit for every PC. Enrollment is one-use
  and expires after 10 minutes. Never reuse/share connector.private.json.
- Keep the connector console open. No connector means Not connected;
  the portal never substitutes its own server inventory.
- Browser pairing is remembered in that browser's local storage. Use Clear
  pairing on a shared browser. Keep private credentials out of Git/chat.
- After restarting the PORTAL, reload/sign in and download/run a fresh kit
  on each endpoint to re-enroll. The registry is currently in memory.
- Do not restart the portal or close connectors during agent operations.
- Wait for operations to finish before Ctrl+C. Closing a browser tab alone
  does not stop the connector or an operation.
- HTTP is unencrypted. Use a trusted LAN and approved file/code sharing.

F. TROUBLESHOOTING

Only the host appears / old host behavior persists:
    Stop the old Python portal after its operations finish, update the full
    webapp source and restart it. Reload the browser. Connect each visiting
    PC using a new kit. Old running Python processes do not reload code.

No connector / offline:
    Start it on that PC; keep its console open. Check outbound access to
    the portal IP/8765. Re-enroll if the portal restarted or the ticket expired.

Unable to bind portal:
    Check ON THE PORTAL:
        Get-NetIPAddress -AddressFamily IPv4
        Get-NetTCPConnection -LocalPort 8765 -State Listen
    Stop the old app in its own terminal; do not kill unrelated processes.

No matching installer / existing agent / restart required:
    Rescan the paired endpoint. Remove the old agent using the approved
    workflow and reboot that endpoint when required. Restarting only the
    connector is not an OS reboot. No substitute distro/CPU kit is selected.

Windows installation appears incomplete:
    Use Verify Windows agent (read-only). It checks the expected MSI product
    and version, vf_agent.exe component and running vf_agent service.
    MSI acceptance alone is not reported as a healthy installation.
    Confirm policy/enrollment in EPM separately. Do not blindly retry.

Manual installation support:
    Download center supplies the private installer/config/key bundle and
    INSTALL-README.txt. Run those instructions on the actual intended PC.

G. OPTIONAL STANDALONE MODE

For intentional management of the same PC running app.py:
    py -3 app.py
    http://127.0.0.1:8765
This loopback-only mode does not require the reverse connector. It does not
make a remote browser PC the target. LAN portal URLs always require pairing.

H. API

Paired endpoint APIs require EPM_API_KEY plus that authorized endpoint's
X-Endpoint-Key capability. See README.md, /integrations and openapi.json.
The legacy native /api/v1/status/install/uninstall APIs are explicitly
host-scoped for existing integrations; visiting-PC automation must use the
new /api/v1/endpoint/rpc and endpoint result polling routes.
