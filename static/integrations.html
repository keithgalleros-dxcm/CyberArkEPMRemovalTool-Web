Checking this PC connector…

First-time setup
  1. Download this private connector kit from the browser on the PC or VM you want to manage.
  2. Extract it into your private user folder. Python 3.11+ is required.
  3. On Windows run Start connector.cmd. On macOS/Linux run sh start-connector.sh.
  4. Keep its console open. The portal detects that endpoint after pairing. Approve UAC on that PC when requested; use its local sudo instructions on macOS/Linux.

The connector makes outbound requests to this portal. No extra inbound endpoint firewall port or browser localhost permission is required. Enrollment expires after 10 minutes. Connector credentials are private; do not share the kit or commit its configuration.

ADMINISTRATOR ACCESS

Request elevation for this console

A web page cannot grant account rights. On Windows, request a local UAC prompt and have an authorized administrator approve it. Approval relaunches this endpoint’s connector as administrator; it does not add your account to an administrators group or start removal.

Checking local privileges…

Manual steps and organizational approval
  1. If you do not have an administrator account or UAC is blocked, contact IT or use your organization’s approved CyberArk EPM / JIT elevation workflow. This app does not submit a service-desk ticket or approve entitlement requests.
  2. For manual relaunch, stop the current console with Ctrl+C in its terminal. On Windows, paste the command below into PowerShell. On macOS, paste it into Terminal and enter the password only in the native terminal prompt.
  3. Open this same local URL again. Confirm the privilege indicator, review the agent and explicitly authorize removal.
Checking the local launch command…

Windows approval may require an administrator to enter credentials on the secure desktop. API-enabled consoles require a manual restart so an administrator can preserve their configuration. Linux inventory guidance does not require elevation.

Connect an AI tool to the paired PC

Run and pair the endpoint connector on the PC or VM to manage. Configure a server EPM_API_KEY and provision that authorized endpoint’s capability securely. Both credentials are required for paired API calls. Do not paste them into chat or URLs.

OpenAPI schema ↗

Paired endpoint API

MethodRoutePurpose
GET/api/v1/endpoint/infoConnection and endpoint hostname
POST/api/v1/endpoint/rpcQueue an allowlisted endpoint operation
GET/api/v1/endpoint/result/{request_id}Poll the paired endpoint response

RPC body: method, path, optional body. Example read: method GET, path /api/status. Installation/removal/elevation use POST and retain native hostname, confirmation and privilege checks. No endpoint connection means no action; the server is never a fallback.

Legacy host-mode APIs

The original /api/v1/status, /api/v1/packages, /api/v1/install and /api/v1/uninstall routes remain explicitly scoped to the app host for existing integrations. Use the paired-endpoint routes above for visiting PCs. Browser requests cannot use these legacy routes to bypass endpoint pairing.

See README.md and examples/client.py in GitHub. Cloud tools must have approved network access to the LAN portal; connector credentials and API keys belong in secure local configuration.
