Checking this PC connector…

Open the downloaded installer on this PC. Setup handles Python detection, file extraction and startup. On macOS/Linux, run sh Install-connector.sh in Terminal.

How installation works
  1. Click Install connector on the PC or VM you want to manage. Open the downloaded installer there; browsers require this user action.
  2. Windows: open Install-connector.cmd. Setup checks Python 3.11+, provisions a private Python runtime if missing, copies connector files into your user application folder and starts it automatically.
  3. macOS/Linux: run sh Install-connector.sh in Terminal. Setup detects Python, installs it if needed using the supported system installer/package manager (sudo approval may be required), and starts the connector.
  4. No manual extraction or copying into the Python folder. Return here and confirm the endpoint hostname. Later agent changes still require explicit confirmation and local UAC/sudo.

Setup logs stay in the connector installation folder. Windows adds a Start menu reconnect shortcut. No connector service or login startup is registered. Enrollment is private, single-use and expires after 10 minutes; if setup takes longer, use a fresh installer. The connector makes outbound requests; no inbound endpoint port is needed.

Manual steps and organizational approval
  1. If you do not have an administrator account or UAC is blocked, contact IT or use your organization’s approved CyberArk EPM / JIT elevation workflow. This app does not submit a service-desk ticket or approve entitlement requests.
  2. For manual relaunch, wait for all jobs to finish, then stop this endpoint connector process listed in its installation folder’s connector.pid. For a foreground console, use Ctrl+C. On Windows, paste the command below into PowerShell. On macOS, paste it into Terminal and enter the password only in the native terminal prompt.
  3. Open this same local URL again. Confirm the privilege indicator, review the agent and explicitly authorize removal.

Checking local distribution…

Removal readiness

  1. Identify the CyberArk product name, package name and installed version from your software inventory or administrator.
  2. Record the Linux distribution and version shown above. Verify that version against the product's support matrix.
  3. Get the documented uninstall procedure and any required approval or secure token from your CyberArk administrator.
  4. Plan a maintenance window and test the procedure on a disposable endpoint before production use.

No package removal commands are generated. EPM, Identity and Privilege products have different removal procedures.

MANUAL OPTION · DISPLAY ONLY

Manual command-line instructions

Copy these commands into a terminal on the endpoint you intend to manage. Copying a command does not execute it. The console does not track removals started in a terminal; rescan afterward.

Read-only Linux identification commands are available below. The console has no automatic Linux removal adapter. Confirm the installed product/version and follow its approved vendor uninstall procedure; no generic removal command is supplied. Package matches are candidates for investigation and do not prove that a package is the EPM agent. No matches can also mean the software was installed outside the package manager.

Identify the Linux distribution

cat /etc/os-release

Check available package inventory tools

command -v dpkg-query rpm pacman

DEB-based systems: inspect package inventory

dpkg-query -W -f='${binary:Package}\t${Version}\n' | grep -Ei 'cyberark|idira|viewfinity|epm'

RPM-based systems: inspect package inventory

rpm -qa --qf '%{NAME}\t%{VERSION}-%{RELEASE}\n' | grep -Ei 'cyberark|idira|viewfinity|epm'

Arch-based systems: inspect package inventory

pacman -Q | grep -Ei 'cyberark|idira|viewfinity|epm'

Share the product name, installed version and distro version with your CyberArk administrator, obtain the exact vendor uninstall procedure, and validate it on an approved test endpoint. Avoid generic purge or file-deletion commands.
